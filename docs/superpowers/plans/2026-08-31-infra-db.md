# Managed PostgreSQL Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `$subagent-driven-development` (recommended) or `$executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provisionar um RDS PostgreSQL privado, pequeno, criptografado e compartilhado por schemas entre hml/prod, com segredo gerenciado, alarmes e lifecycle automatizado.

**Architecture:** O repositório consome a rede e os security groups do remote state de `soat-oficina-infra-k8s`. Uma instância Single-AZ `db.t4g.micro` cria o database `oficina`; os Jobs Flyway da aplicação criam e migram os schemas `hml` e `prod` separadamente.

**Tech Stack:** Terraform `>=1.11,<2.0`, AWS Provider `~>6.0`, PostgreSQL 16, RDS gp3, GitHub Actions, TFLint, Checkov.

**Spec:** `docs/superpowers/specs/2026-08-31-fase-3-aws-design.md`

## Global Constraints

- Região: `us-east-1`.
- Instância: `db.t4g.micro`, Single-AZ, 20 GB gp3, storage autoscaling até 100 GB.
- Database: `oficina`; schemas `hml` e `prod` pertencem à aplicação/Flyway.
- Backup: retenção de 1 dia; `skip_final_snapshot=true`; `deletion_protection=false`.
- Criptografia em repouso e TLS obrigatório.
- RDS nunca é público e aceita 5432 somente do EKS e das Lambdas compartilhadas.
- A senha gerenciada nunca é lida, exibida ou copiada para outputs.
- O mesmo state compartilhado é aplicado por `develop` e revalidado por `main`.

resource "aws_db_parameter_group" "postgres16" {
  name   = "${local.project}-postgres16"
  family = "postgres16"

    name         = "rds.force_ssl"
    value        = "1"

resource "aws_db_instance" "this" {
  identifier = "${local.project}-db"
  engine         = "postgres"
  engine_version = "16"
  instance_class = "db.t4g.micro"
  db_name  = "oficina"
  username = "oficina_admin"
  manage_master_user_password = true

  allocated_storage     = 20
  max_allocated_storage = 100
  storage_type          = "gp3"
  storage_encrypted     = true

  db_subnet_group_name   = aws_db_subnet_group.this.name
  vpc_security_group_ids = [aws_security_group.rds.id]

Mark endpoint and secret ARN outputs as `sensitive = true` even though they do not contain the password. Never create an output for `master_user_secret.secret_status` or secret contents.

- [ ] **Step 2: Run and confirm failure**

- [ ] **Step 3: Implement workflows**

CI on every PR runs fmt, backend-free init, validate, test, TFLint and Checkov with no AWS write credentials. Deploy on `develop`/`main` selects `hml`/`prod`, assumes the environment-specific role, initializes the shared backend key, saves `tfplan`, uploads it, and applies the saved plan. Use one concurrency group `infra-db-shared` with `cancel-in-progress=false`.

Destroy is `workflow_dispatch` and requires `DESTROY-soat-oficina-db`. It creates and waits for a final snapshot named `soat-oficina-final-${UTC_YYYYMMDD}-${GITHUB_RUN_ID}`, applies a saved plan with `deletion_protection=false` targeted to the RDS instance, then creates and applies a full `-destroy` plan with the same variable. Both plans and the final snapshot ARN are uploaded as evidence. The workflow aborts before changing protection if snapshot creation fails.
